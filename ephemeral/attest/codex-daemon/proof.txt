What was left out and why:

- No `thread/resume` fallback for a "thread not loaded" `turn/start`
  failure (for example, after the daemon restarts between turns) was
  added. The task allowed leaving it out if detecting that failure mode
  is not simple, and it is not: `turn/start` gives no reliable, documented
  error shape for "this thread is not loaded" versus any other failure,
  and provoking a real daemon restart to observe it would mean stopping
  the one shared daemon other clients (Codex Desktop) depend on, which is
  exactly what this change must never do. The adapter still recovers from
  a dead connection (redials the shared daemon on the next call), which
  covers the daemon-restart case for the connection itself; only the
  "resume a thread the fresh daemon has not loaded" fallback is left out.
