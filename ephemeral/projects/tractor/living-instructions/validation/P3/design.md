# P3: every promise is marked done in the validation ledger after an independent review routed pass

Archetype: universal over the promises of a run. Checked exhaustively;
no holdout. Lap 2; answers `review-1.md`.

## Story

Any `plan` run the check makes itself at check time
(`validation/lib/run-plan.sh seeds/greeter.md accept-all.rules`). Nothing
that exists before the check is evidence.

## Evidence

- `validation/ledger.md` from the package. Item names are promise ids:
  the ledger is generated by `decompose` from `templates/ledger.md` with
  `name: <id>` per row of `promises.md`.
- `timeline.jsonl`: `LoopValidated(node, item, passed)` for the
  validation loop node; `StageCompleted(name, next)` for `review` and
  `design`.
- `checkpoint.json` `sessions`: the harness recorded for `review` and for
  `design`, and the thread-mode marker on each key.
- Segments of every `design` and `review` stage: `tool_call` arguments.

## Validator

`command`: `prove/p3-independent-review.sh`: the set of item names in
`validation/ledger.md` equals the set of ids in `promises.md`; every item
is `done: true`; for every item there is a `LoopValidated` event on the
validation loop with `passed: true` (engine-marked, not hand-marked);
for each such event the nearest preceding `StageCompleted` is a `review`
stage whose `next` is the loop node; in `checkpoint.json`, the `review`
session's harness differs from the `design` session's harness, and the
`review` key carries the no-thread marker (fresh context each turn); no
`design` or `review` segment contains a `tool_call` whose arguments name
`validation/ledger.md`.

No `infer`.

## Not proven

That the designs are good. That a particular model was used: the run
records the harness (provider route), not the model; `models.yaml` is
static content. That each review turn had a brand-new native session
beyond what the no-thread marker implies; the promise asks for another
provider, not for session accounting.
