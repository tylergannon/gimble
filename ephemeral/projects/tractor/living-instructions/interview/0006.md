# Planning workflow invocation and output

How should callers list and run embedded workflows, and how should the planning
workflow choose its output directory?

## Options

1. **Dedicated `workflow` subcommands (recommended):**
   `tractor workflow list` and
   `tractor workflow run plan --project <build> --seed <path>`. The plan writes
   to `ephemeral/projects/<build>/`. This avoids ambiguity with pipeline paths
   while keeping every named workflow behind one discoverable namespace.
2. **Names accepted by `run`:** `tractor run plan --project <build> --seed <path>`
   and a separate `tractor workflows` listing command. This is shorter, but a
   workflow name can collide with a pipeline path and `run` gains two contracts.
3. **Flag on `run`:**
   `tractor run --workflow plan --project <build> --seed <path>` plus
   `tractor workflows`. This is unambiguous but spreads the surface across two
   commands and makes discovery less direct.

Should `<build>` be required, or should Tractor derive it from the seed and
print the selected path?
