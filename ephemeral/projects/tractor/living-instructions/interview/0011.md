# LARGE planning-output shape

The current `plan` prompt says every `checklist.md` item fits one agent turn and
names only three fixed artifacts. But `large` must run `checklist.md` as a
chapter loop, and its nested sprint loop can resolve a different ledger for
each chapter only when each outer item has a `checklist:` path. The per-chapter
planner also benefits from a `doc:` containing the chapter contract.

What should chapter 3 establish as the LARGE handoff from `plan`?

1. **Make LARGE output execution-ready (recommended).** For a LARGE
   recommendation, `checklist.md` is the chapter ledger. Every chapter item has
   `doc:` pointing to a chapter document and `checklist:` pointing to that
   chapter's initially empty sprint ledger; the planner writes those supporting
   files beneath the project directory. The three named top-level artifacts
   remain fixed, but are not the only files. MEDIUM keeps a flat checklist of
   one-turn sprint items. Extend mechanical plan validation accordingly.
2. **Let `large` bootstrap a flat plan.** Keep the current planner contract and
   add execution-time machinery that converts one-turn items into chapters and
   ledgers before entering the outer loop. This adds a phase not present in the
   intended `chapters -> plan -> sprints` shape.
3. **Require callers to reshape the plan manually.** Document the missing
   scaffold as a step between plan and execution. This makes the emitted
   `Next:` command non-runnable as written.

I recommend option 1 because it makes the chapter-2 handoff directly runnable
and uses the loop node's existing `doc` and `checklist` fields as designed.
