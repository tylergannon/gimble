# LARGE per-chapter planner interview

The LARGE workflow mirrors this build: the outer chapter loop enters a `plan`
codergen node, which populates the current chapter's initially empty sprint
ledger before the inner sprint loop begins. Should that `plan` node be allowed
to ask the reviewer through blocking `tractor ask` calls?

1. **Allow questions only when material (recommended).** The planner reads the
   overall brief/checklist plus the current chapter doc, asks one question at a
   time only where an answer changes sprint scope or validation, then writes
   the sprint docs and ledger in the same agent turn. It plans silently when
   the chapter is already derivable.
2. **Always plan silently.** The chapter doc is authoritative and any ambiguity
   must be preserved in the sprint rather than resolved before execution. This
   reduces interruption but risks invented validators or underspecified work.
3. **Require at least one question per chapter.** This guarantees human review
   but interrupts even when the brief and chapter doc already settle the plan.

I recommend option 1. It matches the existing build's planning prompt, keeps
questions proportional, and avoids making ceremony mandatory.
