# Planning workflow interview shape

What graph shape should the embedded `plan` workflow use for its interview?

## Options

1. **One codergen node that owns the whole interview (recommended):** give it a
   deliberately long turn timeout and instruct it to call `tractor ask` once per
   material uncertainty, stopping when the contract is clear. It then writes
   the artifacts before exiting. This matches the ratified requirement that the
   agent retain one context across the interview and needs no new routing state.
2. **One interview codergen node, then a separate writer codergen node:** the
   first asks questions and writes structured interview notes; the second reads
   those notes and writes the three outputs. This separates duties but spends a
   second turn and can lose tacit context at the handoff.
3. **A loop of short codergen visits:** each visit asks at most one question and
   persists state for the next visit. This makes each wait bounded but conflicts
   with the decision that `ask` blocks inside a single node visit and adds state
   machinery the project has rejected.

If option 1 is chosen, should artifact writing happen in that same node, or in a
following deterministic/non-agent node?
