# Recommendation artifact and caller handoff

What exact recommendation artifact should the planner write, and how should a
caller read the result?

## Options

1. **`recommendation.md` with a small fixed contract (recommended):** a heading,
   `Size: SIMPLE|MEDIUM|LARGE`, a short rationale, and `Next:`. For SIMPLE,
   `Next` says `Execute the plan yourself.` For MEDIUM/LARGE it contains the
   exact `tractor workflow run ...` command supplied by chapter 3. On success,
   `tractor workflow run plan` prints the paths of all three artifacts and the
   size/next-action summary, so scripts can find files and people get the handoff
   without opening one first.
2. **`recommendation.yaml`:** fixed fields for size, rationale, and next command,
   with the CLI printing only its path. This is easy to parse but makes the
   primary planning output less pleasant to read and introduces a fourth format.
3. **Recommendation section in `brief.md`:** only two output files; the CLI
   prints the section. This is compact but contradicts the ratified three-output
   handoff and makes the recommendation harder to validate independently.

For MEDIUM/LARGE, may chapter 2 establish provisional workflow names now, or
should it emit a named placeholder until chapter 3 fixes those names?
