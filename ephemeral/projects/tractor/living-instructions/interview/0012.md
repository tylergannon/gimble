# Execution workflow logs contract

The ratified recommendation emits exactly:

```text
tractor workflow run medium --project <build>
tractor workflow run large --project <build>
```

But `tractor workflow run plan` currently requires `--logs`, as does the shared
runner. Should those emitted execution commands work without another flag?

1. **Give execution workflows a default logs directory (recommended).** For
   `medium` and `large`, make `--logs` optional and allocate a fresh run
   directory beneath a conventional Tractor state root or the project. Keep
   `--logs` as an override. `plan` may retain its current required `--logs`
   because callers invoke it directly rather than through a fixed handoff.
2. **Require callers to append `--logs`.** Keep runner parity, but the emitted
   `Next:` value is only a command prefix despite being documented as the exact
   next action.
3. **Change the recommendation contract.** Emit a `--logs <path>` placeholder
   in `Next:`. This revisits the fixed chapter-2 contract and still is not
   directly runnable until edited.

I recommend option 1 so the fixed handoff is executable as printed while still
allowing explicit log placement for automation.
