# Adapted df-semantic-index method

**Purpose.** This local reference describes a filesystem semantic index: a compact routing tree over a separate local token cache, used to find source evidence without loading the full corpus. It is adapted here for question-specific programmatic-workflow research, not adopted as a requirement for embeddings, a vector database, or a particular serialization format.

**Findings.**

- The method distinguishes the complete local **token cache** from the compact **semantic index**, and requires the cache to remain an actual POSIX filesystem for direct retrieval (`corpus/method/df-semantic-index-SKILL.md:9-14`). For this research, `corpus/` is the immutable copied-source cache and `index/` is the separately authored task-routing tree.
- The required surfaces are an entrypoint, routing nodes, citation-bearing leaves, housekeeping state, and retrieval evaluation (`corpus/method/df-semantic-index-SKILL.md:36-46`). The adaptation preserves the important parts: routes narrow by research question/source family; leaves cite `corpus` paths and pinned URLs; index-wide status/evals are the integrator's responsibility.
- The source explicitly leaves storage format flexible—human-readable Markdown is preferred for small/medium indexes and SQLite/structured forms are only a scale option (`corpus/method/df-semantic-index-SKILL.md:38-46`). No embedding model, vector store, or semantic similarity service is required by this method.
- The first pass calls for a cheap corpus/index inspection, an explicit operating mode, and segmentation only for larger source sets (`corpus/method/df-semantic-index-SKILL.md:75-90`). The present work is a scratch build with bounded, assigned source families; leaves are written directly because each lane is small.
- A leaf should give purpose, anchored concepts/citations, themes, gotchas, and task-oriented retrieval recipes; it must not write routing files (`corpus/method/df-semantic-index-SKILL.md:146-165`). This is why the leaves report both source mechanism and its limits rather than acting as a generic project survey.
- The method treats benchmarks as evidence of retrieval quality, with expected routes/citations and reachability metrics (`corpus/method/df-semantic-index-SKILL.md:218-257`), and says the index is unfinished if agents still need filename browsing (`corpus/method/df-semantic-index-SKILL.md:386-394`). The later [retrieval review](../.semantic-index/retrieval-review.md) and [structural audit](../.semantic-index/state.json) record an unblinded smoke exercise and index checks. They establish neither a baseline nor a demonstrated speed or retrieval-quality advantage.

**Adapted operating rules.** Copy only necessary upstream text/source into `corpus/`, pin it with a manifest/hash/license evidence where available, then do not alter it while writing index leaves. Keep task-first routing separate from source snapshots. Cite exact local `corpus/...:line` anchors plus pinned URLs where they exist. Record unknowns, vendor claims, and stale/status limits in each leaf so a routed agent can distinguish observed source from inference. The copied method's cache/index storage distinction should not be read as two kinds of agent context; [the direction document](../../../../../../docs/direction.md) describes the current unified-context direction.

**Gotchas.** The method's suggested helper scripts and project-root `docs/SEMANTIC-INDEX.md` integration are not automatically appropriate for this temporary research project; avoid creating permanent product docs from an exploratory corpus. Metrics are signals, not policy (`corpus/method/df-semantic-index-SKILL.md:301-319`). A copied source is not runtime proof, and an index citation is not permission to infer behavior not present in that source.
