# Cross-source themes

## The language boundary is a design diagnosis

The argument is not simply that Go is familiar or concise. A graph shorthand
that attempts to model workflow in general must reproduce ordinary programming
constructs, while agentic-workflow tactics change quickly. The proposed
response is to let Go express the method directly and keep the orchestration
algorithm visible. See [go-authorship](routes/go-authorship/index.md).

## Program freedom is subordinate to successful context engineering

Go supplies the control-flow substrate, but the main optimization target is an
agent reaching its goal accurately, quickly, and cheaply. Goals, requirements,
rules, current work, feedback, indexed material, and on-disk artifacts form one
agent context. A compact entry point should make the objective clear and route
the agent to further information. See [context-and-indexing](routes/context-and-indexing/index.md).

## Legibility survives as a constraint on the new API

A good graph's useful promise is that a reader can understand stages and
progression. Go should retain that property through source that resembles
pseudocode, visible decisions, meaningful names, and inspectable context
choices. Static analysis and agent-assisted diagrams may explain the program,
but they do not define execution. See [legibility](routes/legibility/index.md).

## Information work belongs inside workflow design

Research and indexing are companions to coding and validation. The relevant
material should be local, searchable, and connected to the task; the index can
evolve as findings and artifacts accumulate. This is why the index is part of
the starting context rather than an afterthought. See [context-and-indexing](routes/context-and-indexing/index.md).

## Division of responsibility is both safeguard and tradeoff

Builder, supervisor, and checker agents distribute attention across roles and
time, reducing what one agent must remember. The same split creates handoff
cost and can obscure the whole, so every participant still needs the larger
objective. This is the program direction's direct connection to the
[five arts](routes/roles-and-evaluation/index.md).

## Status boundaries matter

The Go-program runtime, automatic structural views, unified context assembly,
and comprehensive telemetry are proposals. Good supervision is the only
concrete recovery approach identified so far. The edited documents and
corrections explicitly retain these as direction rather than shipped behavior.
See [status-and-contract](routes/status-and-contract/index.md).
